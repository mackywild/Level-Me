# EXP付与・クエスト・旧報酬の境界安全化

RV-147/RV-145/RV-141の部分対応。Dartネイティブ符号付き64bit上限（9223372036854775807）を対象とする。EXP、属性EXP、完了件数、旧ガチャ券、旧最大HP、旧ボス討伐回数、旧G報酬の加算は超過・負値を拒否し、報酬を切り捨てない。攻撃エネルギー9999・旧HP最大値までの回復は従来どおり飽和するが加算前に残容量を比較する。

- 時間報酬の正のEXP四捨五入（EXP×分倍率÷25、最小1、倍率1〜120）はBigIntで中間積と丸めを計算する。巨大値で従来doubleの精度差が出る場合はあるが通常性能は維持。新規クエストの報酬総和も登録前に検証し、報酬一覧をコピーする。
- _grantRewardsは複数・同一属性の報酬と総EXPを作業用の集計値で全件検証後に反映する。既存Controller直列トランザクションが完了フラグ、セッション履歴、見直しクエスト、称号、資源等を例外時に復元する。上限拒否では保存を開始しない。称号の追加付与も同一契約。負のtotalExpのレベル計算互換は維持するが負残高からの報酬付与は拒否する。
- 旧ボス勝利80G/討伐数+1を事前境界比較で検証し、反撃の討伐数係数は乗算前に上限10で制限する。旧ガチャ50Gも超過拒否し券を状態復元、エネルギー報酬は従来の上限付き加算。旧ガチャの乱数注入は境界試験用、本番は従来Random.secure。拒否時の乱数消費自体は取り消さない。旧抽選の確定保存は対象外。
- 保存形式・本番master・公開フラグ・通常報酬値は変更しない。既存の負値や異常なクエスト定義の包括的な移行・起動時検証は別課題。今回の例外時復元は既存のトランザクションを利用しており、全経路の保存成功前非公開化や書込途中の障害回復を新規に保証するものではない。
